> **日期**：2026-08-17  
> **范围**：居民端 `apps/miniapp-customer`、员工端 `apps/miniapp-worker`  
> **对照**：企业认证主体、服务类目、隐私接口、代码审核规范

企业认证只解决主体资格。类目、备案、HTTPS 域名、隐私指引、地理位置接口开通都要在公众平台单独完成，代码侧也有必须改的点。

## 1. 优先处理（P0）

| 优先级 | 问题 | 影响 | 怎么处理 |
|---|---|---|---|
| P0 | 两端共用 AppID `wx02b6a6438695bf92` | 一个 AppID 只能发一份代码，居民端和员工端无法同时上线 | 再注册一个企业小程序给员工端；居民端用已认证账号 |
| P0 | 生产 API 为 `http://118.195.149.50` | `request` / `uploadFile` 合法域名必须是 HTTPS 备案域名，不能用 IP 或 HTTP | 备案域名 + HTTPS 证书，写入 `VITE_API_BASE`，并打开 `urlCheck` |
| P0 | 小程序 ICP 备案未完成（代码侧无法验证） | 2023 年后未备案不能发布 | 公众平台完成备案，经营内容勾选家政、回收 |
| P0 | 协议写「公司全称待补充」 | 审核明确拒占位文案、不完整主体信息 | 填营业执照全称、客服电话、邮箱 |
| P0 | 员工登录预填 `15610203040` / `123456`，协议默认勾选 | 测试数据 + 默认勾选协议都会被拒 | 清空预填，协议默认未勾选 |
| P0 | 定位失败可「模拟签到」北京坐标 | 正式包出现模拟入口会被判功能不完整或作弊 | 用条件编译只留开发工具，正式包删除 |

## 2. 两端业务是否符合企业主体

### 2.1 居民端（建议先上线）

保洁预约、废品回收、家政咨询。企业认证后可以选「生活服务 - 家政服务」和「商业服务 - 环保回收/废品回收」，这两类目前通常无额外许可证。

现有接口：`wx.login`、手机号组件、选图、拨号。无支付、无定位。

### 2.2 员工端（需独立 AppID）

接单、GPS 签到、作业拍照。业务上属于家政履约工具，类目可走家政服务或办公。`getLocation` 必须先过类目，再在「接口设置」开通。

手机号 + 密码登录，不调用 `wx.login`。位置、相机是审核重点。

## 3. 产品规范缺口

- 居民端首页同意隐私后立刻弹手机号授权，浏览首页也会被挡住。微信要求手机号只在业务必要时（如下单联系）再取，不能作为使用小程序的前提。
- 自研 `PrivacyModal`（首页《用户协议》《隐私政策》）**不能替代**公众平台的《用户隐私保护指引》。两套同意各管各的，见 [第 6 节](#6-微信公众平台用户隐私保护指引必配)。
- 隐私文案写了收集昵称头像、支付信息，代码里没有 `getUserProfile` / `requestPayment`。指引声明必须和真实接口一致。
- 「我的」只有退出登录，注销账号写的是联系客服。建议做入口或写清客服路径，并填真实联系方式。
- Banner 外链会跳到不存在的 `/pages/webview/index`。提审前关掉这类入口，或补页面并配置业务域名。

## 4. 接口对照

企业认证已覆盖：非个人主体且完成微信认证后，才能用手机号快速验证组件。`getLocation` 还要类目在开放名单内，并在「开发 → 开发管理 → 接口设置」单独开通；代码里 `requiredPrivateInfos` 已声明还不够。

### 4.1 居民端实际调用

| 能力 | 代码位置 | 企业认证后 | 后台还要做的 |
|---|---|---|---|
| `wx.login` | 首页 / `ProfileCompleteModal` | 可用 | 配置 AppID + Secret；服务端 `code2session` |
| `getPhoneNumber` | `ProfileCompleteModal` 按钮 | 企业认证后可用；个人主体不行 | 隐私指引勾选「手机号」；购买手机号资源包；不要强制授权 |
| `uni.chooseImage` 相机/相册 | 评价、投诉 | 可用 | 隐私指引勾选「选中的照片或视频」 |
| `uni.uploadFile` / `uni.request` | `api/request.ts`、`upload.ts` | 可用 | request / uploadFile 合法域名必须是 HTTPS 备案域名 |
| `uni.makePhoneCall` | 客服、订单详情 | 可用 | 无需类目；号码须真实可接通 |
| `uni.previewImage` | 订单详情、投诉详情 | 可用 | 无 |
| `getLocation` / 支付 / 分享 | 未使用 | — | 不要在隐私指引里勾选未用的项 |

### 4.2 员工端实际调用

| 能力 | 代码位置 | 企业认证后 | 后台还要做的 |
|---|---|---|---|
| `uni.getLocation` gcj02 | `task-detail` 开始服务 | 类目开放后可申请 | 申请 `wx.getLocation`；隐私指引勾选位置；录屏说明签到场景；去掉模拟签到 |
| `requiredPrivateInfos: getLocation` | `manifest.json` 已写 | 声明正确 | 未开通接口权限时，提审会被拦 |
| `uni.chooseImage` 相机/相册 | 服务前/后照片 | 可用 | 隐私指引勾选相册/相机 |
| `uni.uploadFile` / `uni.request` | `api/request.ts`、`upload.ts` | 可用 | 与居民端同一套 HTTPS 域名 |
| `uni.makePhoneCall` | 联系客户/管理员 | 可用 | 无 |
| `wx.login` / `getPhoneNumber` | 未使用（手机号+密码） | — | 员工端不必买手机号资源包 |

### 4.3 代码声明 vs 微信要求

**已对齐**

- 员工端 `permission.scope.userLocation` 说明是签到核验现场，用途合理。
- 员工端 `requiredPrivateInfos` 已含 `getLocation`。
- 未使用 `requestPayment`，首发不必申请微信支付。

**未对齐**

- `urlCheck: false`，正式包应改为 `true`。
- 公众平台《用户隐私保护指引》尚未按本项目实际接口勾选（见第 6 节）。未配置时，真机上手机号 / 相册 / 定位会被关掉；开发环境点授权入口也不会出现微信官方弹窗。
- 隐私文案写了昵称头像、支付，接口未用。
- 居民端后续若做 `chooseLocation`，要再声明并申请该接口。

## 5. 类目与资质

企业主体可选个人不能选的生活服务类目。营业执照经营范围需覆盖对应业务，否则备案或类目审核会被退回。

| 端 | 建议类目 | 覆盖功能 | 资质 | 经营范围建议 |
|---|---|---|---|---|
| 居民端 | 生活服务 - 家政服务 | 保洁预约、家政咨询 | 通常无许可证，选了即审 | 家政服务、清洁服务等 |
| 居民端 | 商业服务 - 环保回收/废品回收 | 上门废品回收 | 通常无许可证 | 再生资源回收、废旧物资回收 |
| 员工端 | 生活服务 - 家政服务（首选） | 接单、签到、作业记录 | 同家政 | 与居民端同一主体即可 |
| 员工端备选 | 工具 - 办公 / 信息查询 | 仅内部员工使用时 | 无 | 名称和简介写清「员工端，不面向顾客」 |

废品回收不要只挂在家政下面。首页有独立「废品回收」入口，协议也写了回收品类与现场结算。只选家政服务，审核可能判类目不全。回收与保洁一起上，就把两个类目都加上。

### 5.1 接口与类目绑定

**手机号组件（仅居民端）**

企业认证已满足主体条件。还要：隐私指引声明手机号；付费管理购买资源包（有免费额度）；用户点击按钮授权，不能静默取号。建议把授权从启动弹窗改到下单联系人步骤。

**地理位置（仅员工端）**

`wx.getLocation` 只对部分类目开放，家政服务一般在名单内。顺序：类目通过 → 接口设置申请 `wx.getLocation`（附签到录屏）→ 代码 `requiredPrivateInfos` 已有 → 再提审。员工端若选「办公」可能拿不到定位权限，所以内部工具也更稳妥挂家政服务。

**不需要现在申请的**

微信支付、`getUserProfile`（已回收）、`chooseLocation`、`openLocation`、订阅消息、客服消息。计划里的服务号模板消息是另一条产品线，首发可不做。

### 5.2 备案服务内容（与类目分开）

小程序备案的「服务内容」和后台「服务类目」是两套。备案时可勾选生活服务-家政，以及与回收对应的服务内容。备注写清：社区上门保洁预约、废旧物资上门回收、家政咨询，不涉及开锁、金融、医疗。

## 6. 微信公众平台：用户隐私保护指引（必配）

本项目用了隐私接口，**上线前必须在公众平台填写《用户隐私保护指引》**。代码里「我的 → 微信隐私授权」只是调试入口，**不是产品硬条件，试完可删**。

### 6.1 两套同意，不要混

| | 小程序内自研弹窗（`PrivacyModal` / 登录勾选协议） | 公众平台《用户隐私保护指引》 |
|---|---|---|
| 同意的是什么 | 你们公司的《用户协议》《隐私政策》 | 微信侧收集手机号 / 相册 / 位置的规则 |
| 记录在哪 | 本地 `hasAgreedPrivacy` | 微信与该用户、该小程序绑定 |
| 审核 / 运行 | 审核会看协议是否完整、主体是否真实 | **不配则发布后隐私接口被禁用** |
| 是否必须 | 必须有完整协议页（主体名称、联系方式） | **必须在公众平台勾选，且与真实接口一致** |

`wx.login`、下单、拨客服电话不走这套隐私授权。会卡住的是：居民端 `getPhoneNumber`、两端 `chooseImage`、员工端 `getLocation`。

### 6.2 后台怎么填（按本项目勾选）

登录 [微信公众平台](https://mp.weixin.qq.com) → **设置 → 服务内容声明 → 用户隐私保护指引**（入口名称可能略有出入，在「设置」里搜「隐私」即可）。

**居民端小程序勾选：**

- 收集你的手机号（对应 `getPhoneNumber`）
- 收集你选中的照片或视频信息（对应评价 / 投诉 `chooseImage`）

**不要勾：** 昵称头像、位置信息、微信支付。本端代码未使用。

**员工端小程序勾选：**

- 收集你的位置信息（对应签到 `getLocation`）
- 收集你选中的照片或视频信息（对应作业前/后照片）

**不要勾：** 手机号。员工端是账号密码登录，未用 `getPhoneNumber`。

指引里还要填：**开发者主体全称**（与营业执照一致）、**联系邮箱 / 电话**（用户行使查阅、删除权）。不要留「待补充」。

保存后，开发者工具重新编译。未保存前调用 `wx.requirePrivacyAuthorize` 会直接 success、**不弹微信官方窗**，这是微信既定行为，不是按钮坏了。

### 6.3 代码侧要不要专门接授权 API

| 项 | 是否必须 | 说明 |
|---|---|---|
| 公众平台填指引 | **必须** | 否则上线后取号、选图、定位不可用 |
| 首页自研协议弹窗 | **必须保留** | 管的是和公司的约定；审核会看 |
| 用户点「一键授权手机号」或选图时的微信弹窗 | 指引配好后平台可自动弹出 | 不必单独做一页「去授权」 |
| 把「同意并继续」做成 `open-type="agreePrivacyAuthorization"` | 建议 | 首次同意可同时同步给微信 |
| 「我的 → 微信隐私授权」 | **不必** | 仅方便本地试 `requirePrivacyAuthorize`，上线前可删 |

已授权过的用户再次调用不会弹窗。开发者工具可在 **详情 → 本地设置** 清除授权数据后再试。

## 7. 上线清单

### 7.1 公众平台配置

- [ ] 居民端用已认证小程序；员工端再注册一个企业小程序并认证，改各自 `manifest.appid`
- [ ] 居民端添加：家政服务 + 环保回收/废品回收；员工端添加家政服务
- [ ] 完成小程序 ICP 备案（未备案不能发布）
- [ ] 备案 HTTPS 域名，配置 request / uploadFile 合法域名；不要填 IP
- [ ] **居民端**填写《用户隐私保护指引》：手机号 + 选中的照片或视频；主体名称、联系邮箱必填；不要勾昵称头像 / 位置 / 支付
- [ ] **员工端**填写《用户隐私保护指引》：位置信息 + 选中的照片或视频；不要勾手机号
- [ ] 员工端开通 `wx.getLocation`，提交签到场景录屏
- [ ] 居民端购买手机号快速验证资源包（或确认免费额度）
- [ ] 生产环境填写 `WECHAT_CUSTOMER_APPID` / `SECRET`，关闭 mock 登录

### 7.2 代码必须改完再提审

- [ ] `VITE_API_BASE` 改为 `https://你的备案域名/api/v1`，`urlCheck` 改为 `true`
- [ ] 用户协议/隐私政策替换「公司全称待补充」「客服电话待补充」；删掉未使用的昵称头像、支付描述
- [ ] 员工登录去掉预填账号密码，协议默认未勾选
- [ ] 正式包删除「模拟签到」
- [ ] 不要一进首页就强制手机号；浏览可匿名，下单再授权
- [ ] 「我的」增加注销说明或入口，联系方式与协议一致
- [ ] 去掉不存在的 webview 跳转，或补页面并配业务域名
- [ ] （可选）删除「我的 → 微信隐私授权」调试入口；不删也不挡审核，但正式包建议拿掉

### 7.3 提审材料

| 材料 | 居民端 | 员工端 |
|---|---|---|
| 小程序名称/简介/头像 | 面向居民的预约服务，避免「测试」「demo」 | 名称带「员工端」，简介写内部接单 |
| 类目 | 家政服务 + 废品回收 | 家政服务 |
| 审核备注 | 说明预约流程、无在线支付、客服电话可接通 | 说明仅员工使用，GPS 用于上门签到 |
| 测试账号 | 可走微信登录的体验者；写清无支付 | 真实员工测试号，不要用 `123456` |
| 录屏（建议） | 首页 → 预约保洁 → 下单 → 订单详情 | 登录 → 接单 → 定位签到 → 上传照片完成 |

---

## 8. 建议上线顺序

1. 把已认证的小程序只给居民端。
2. 配好类目、备案、HTTPS、协议正文，并在公众平台填好《用户隐私保护指引》后再提审。
3. 员工端另开一个 AppID，等 `wx.getLocation` 开通后再发。
4. 两端不要挤在同一个 AppID。
